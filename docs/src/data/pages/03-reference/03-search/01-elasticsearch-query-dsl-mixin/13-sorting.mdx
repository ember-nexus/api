This example uses the [long form](/reference/search/elasticsearch-query-dsl-mixin#step-query) of the query. The full
text search for "lily" is sorted by the name of the plants in ascending order, instead of by relevance. The search is
restricted to plants, and only the first five results are returned.

Text properties like `name` can not be sorted directly, therefore the example sorts by `name.keyword`, the exact value
of the property. The [hydrated](/reference/search/element-hydration#metadata) elements keep the order and contain the
values they were sorted by in `metadata.sort`. The score is still calculated and available as `metadata.score`, it
just does not decide the order. To sort by relevance first and use a property as a tie-breaker, use
`"sort": ["_score", {"name.keyword": "asc"}]`.

The next page of results, requested with the step parameter `page`, continues the same order.
