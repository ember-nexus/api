Loads a previously created local backup into the database, restoring its nodes, relations, and
files.

The `name` argument is required and must match an existing backup folder containing a
`summary.json` (as created by `backup:create` or `backup:fetch`). Nodes and relations are imported
in batches, files are re-uploaded to object storage, and a final pass re-dispatches update events
for every imported node and relation so that dependent systems (such as the search index) pick up
the restored data; the Redis cache is flushed at the end of the process.

Options:

- `--skip-verify` - skips verifying file contents against their stored `file.hash` values. Without it, files that
  fail verification are skipped and reported as errors on the console and in the logs; the element keeps
  `hasFile=true` and the command's exit code stays `0`.
- `--skip-mphf-build` - does not build the [element type index](/command/mphf-build) after loading; run `mphf:build`
  afterwards instead.

The node labels and relation types are read from the `graphStructure` of the `summary.json`, and the id indices (see
[`index:ensure`](/command/index-ensure)) for all of them are created before the first element is loaded, so that nodes
and relations are never matched without them. Backups from before the summary contained the graph structure are
loaded the old way: the indices are created after the nodes and after the relations. When everything is loaded, the
cached graph structure is dropped and read again from the loaded database, and the element type index is built at the
end. The command takes the maintenance locks, so these tasks stay quiet in the meantime.

Backups are loaded as they are, their content is never rewritten. Which backups can be loaded is decided by the
`version` property of the `summary.json`: backups created before 0.2.0 use an older format and are refused, with the
suggestion to convert them using [`backup:convert`](/command/backup-convert) first. Backups of development builds
(`dev`) and backups without a version are loaded. Ids with timestamps in the future are imported as they are, and a
warning is logged.

<Note>
    The target database must be empty - the command checks for existing nodes or relations up
    front and refuses to run otherwise. Loading into a non-empty database is not supported.
</Note>
