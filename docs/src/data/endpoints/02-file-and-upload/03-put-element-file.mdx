---
endpoint: put-element-file
group: file-and-upload
method: put
name: Put element file
endpointUrl: /<uuid>/file
swaggerUrl: /{uuid}/file
---

Behaves exactly like [`POST /<uuid>/file`](/api/post-element-file) - the same `Upload-Complete`, `Upload-Length`,
`Content-Disposition` and `Repr-Digest` headers select between a direct upload (`201 Created`) and a resumable upload
(`204 No Content` with a `Location` header), verify upload integrity, and the same `Upload-Limit` rules apply to
chunk sizes.

The only difference is that this endpoint does not require the element to be empty: if it already has a file
attached, that file is replaced once the (possibly resumable) upload completes - including replacing it with a file
of a different extension, e.g. overwriting a `.jpg` with a `.txt`. The old file is removed from storage as part of
the replacement.

Conditional requests: `If-Match: *` and `If-None-Match: *` are supported, a failing precondition answers `412`
(evaluated before any `409`), and `If-Match` on an element without file answers `412`. Without the required access,
conditional requests answer `404`.

<Note>
    Because a replacement is destructive, this endpoint supports `If-Match` against the current file's `ETag`,
    letting concurrent writers detect that the file changed since it was last read. `POST` has no such check, since
    it can only ever create a file, never overwrite one.
</Note>

<Note>
    If a `Repr-Digest` (or `Content-Digest`) sent with the upload does not match the uploaded content, the request
    fails with `400 Bad Request` and the existing file is left untouched - a failed replacement never leaves the
    element without a file, or with a partially-written one.
</Note>
